> BREVETTO CONCESSO · US7716225B1

Ranking basato su comportamento utente e caratteristiche dei link

Titolo originale: Ranking documents based on user behavior and/or feature data

Il brevetto descrive un sistema per assegnare pesi ai link tra documenti basandosi sulla probabilità che vengano selezionati dagli utenti. Costruisce un modello predittivo analizzando dati comportamentali (quali link sono stati cliccati) e feature dei link (dimensione font, posizione, anchor text, ecc.), poi usa questo modello per calcolare il ranking dei documenti.

> COSA RIVENDICA

La rivendicazione indipendente 1 descrive un metodo che memorizza feature data per una pluralità di link (caratteristiche del documento sorgente, del documento target e del link stesso) e user behavior data relativi all'attività di navigazione degli utenti. Il sistema addestra un modello che identifica la probabilità che un particolare link con determinate feature venga selezionato, analizzando le feature dei link che sono stati selezionati versus quelli non selezionati per generare regole. Il modello viene poi applicato a nuovi link: si determina la feature data, si calcola la probabilità di selezione tramite il modello, si assegna un peso al link basato su tale probabilità, e infine si calcola un rank per il documento target basandosi sui pesi dei link che lo puntano e sul rank dei documenti sorgente.

La rivendicazione 5 specifica che le feature del documento sorgente possono includere: indirizzo completo o parziale, informazioni sul sito web, numero di link nel documento, presenza di parole nel documento o negli heading, topical cluster associato al documento, grado di corrispondenza tra il cluster tematico del documento e quello del link. La rivendicazione 6 elenca feature del link: dimensione font dell'anchor text, posizione del link nel documento, posizione in una lista, colore del font, attributi del link, numero di parole nell'anchor text, parole effettive nell'anchor text, commercialità dell'anchor text, tipo di link, contesto delle parole prima/dopo il link, topical cluster dell'anchor text, se il link porta a un documento sullo stesso host/dominio, se l'URL del link incorpora un altro URL. La rivendicazione 7 copre feature del documento target: indirizzo completo o parziale, informazioni sul sito web, se l'indirizzo è sullo stesso host o dominio del documento sorgente, parole nell'URL, lunghezza dell'URL.

Le rivendicazioni 3 e 4 specificano che i dati comportamentali possono corrispondere a un singolo utente o a una classe di utenti. La rivendicazione 10 indica che le regole del modello comprendono sia regole generali applicabili a gruppi di documenti sia regole specifiche per documenti particolari. La rivendicazione 11 prevede l'aggiornamento periodico delle regole basato sui cambiamenti nei dati comportamentali. La rivendicazione 12 ribadisce il metodo con enfasi sull'assegnazione di pesi ai link e sul calcolo del rank basato su tali pesi.

> LETTURA SEO (INTERPRETAZIONE)

La descrizione contempla un "reasonable surfer model" che riflette il fatto che non tutti i link hanno uguale probabilità di essere seguiti (paragrafo Overview). Il sistema raccoglie user behavior data tramite browser o browser assistant che registrano quali link vengono selezionati, la lingua dell'utente, gli interessi, i termini di ricerca (sezione Repository 430). La descrizione fornisce liste dettagliate di feature: per i link include font size dell'anchor text, posizione (in lista HTML, nel testo, sopra/sotto il primo schermo visibile su browser 800x600, lato del documento, footer, sidebar), posizione nella lista se applicabile, colore e attributi del font (italics, grigio, stesso colore dello sfondo), numero di parole nell'anchor text, parole effettive, commercialità dell'anchor text, tipo di link (es. image link), aspect ratio se è un'immagine, contesto di poche parole prima/dopo, topical cluster dell'anchor text, se porta allo stesso host/dominio, se l'URL del link è più corto dell'URL referrer quando sullo stesso dominio, se l'URL incorpora un altro URL per redirezione server-side (sezione Repository 430, feature dei link).

Il modello viene costruito identificando istanze positive (link selezionati) e negative (link non selezionati nello stesso documento) e generando feature vector per ciascun link. Il sistema impara regole generali e document-specific: esempi di regole generali contemplati includono che link con anchor text di font size maggiore hanno probabilità più alta di selezione, link posizionati più in alto nel documento hanno probabilità maggiore, link dove il topical cluster del documento sorgente è correlato a quello del target hanno probabilità maggiore (sezione Model generating unit 410). Esempi di regole document-specific contemplati: un link sotto l'heading "More Top Stories" su cnn.com ha alta probabilità di selezione, link con URL target contenente "domainpark" hanno bassa probabilità, link in documenti con popup hanno bassa probabilità, link a domini che finiscono in ".tv" hanno bassa probabilità, link con URL contenenti multipli trattini hanno bassa probabilità (sezione Model generating unit 410).

La formula per il ranking (Eqn. 1) mostra che il rank di un documento A dipende dai rank dei documenti che lo linkano (B1...Bn), dai pesi assegnati ai backward link (w1...wn), e dal numero di forward link nei documenti sorgente. Il peso di un link riflette la probabilità che venga selezionato secondo il modello. Questo potrebbe significare che Google potrebbe valutare i link non solo per la loro esistenza ma per la probabilità che siano effettivamente utili e cliccati dagli utenti, penalizzando link in posizioni poco visibili, con formattazione poco attraente, o in contesti non pertinenti. Potrebbe anche significare che link in footer, sidebar, o con caratteristiche tipiche di link pubblicitari o di servizio ("Terms of Service") potrebbero contribuire meno al ranking. La personalizzazione per classi di utenti o singoli utenti suggerirebbe che il valore di un link potrebbe variare in base al contesto dell'utente.

> COSA FARE COMUNQUE

  1. Concentrarsi su link che appaiono in posizioni naturalmente visibili e cliccabili (corpo principale del contenuto, contesto pertinente) piuttosto che in footer, sidebar o sezioni di servizio.
  2. Curare l'anchor text dei link in modo che sia descrittivo, pertinente al contenuto linkato e al contesto circostante, evitando formattazioni che suggeriscono pubblicità.
  3. Assicurarsi che i link interni ed esterni siano contestualmente rilevanti rispetto al topic del documento sorgente e del documento target.
  4. Evitare pattern tipici di link di bassa qualità: URL con molti trattini, domini sospetti, redirezioni multiple, link in documenti con popup o elementi invasivi.

> TERMINI CHIAVE

reasonable surfer model
Modello che assume che un utente che naviga tra documenti seguirà alcuni link con probabilità maggiore di altri, a differenza di modelli che trattano tutti i link ugualmente
feature data
Caratteristiche misurabili associate a link, documenti sorgente e documenti target, come dimensione font, posizione, anchor text, URL, topical cluster
user behavior data
Dati relativi alle azioni di navigazione degli utenti, inclusi quali link sono stati selezionati, termini di ricerca, lingua, interessi
selection rate
Probabilità che un link venga selezionato da un utente, calcolata dal modello in base alle feature del link
topical cluster
Raggruppamento tematico con cui un documento o anchor text è associato, usato per valutare la pertinenza tra documenti collegati
positive/negative instances
Istanze positive sono link che sono stati cliccati; istanze negative sono link presenti ma non cliccati nello stesso documento
feature vector
Rappresentazione strutturata delle feature di un link usata come input per il modello predittivo
