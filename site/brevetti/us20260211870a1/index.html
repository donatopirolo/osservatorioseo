> DOMANDA DI BREVETTO · US20260211870A1

Generazione di varianti di query tramite modello generativo

Titolo originale: Generating query variants using a trained generative model

Il brevetto descrive un sistema per generare varianti di una query originale utilizzando un modello generativo addestrato (tipicamente sequence-to-sequence con layer di memoria come LSTM). Le varianti possono essere di diversi tipi (equivalenti, follow-up, generalizzazioni, canonicalizzazioni) e vengono generate applicando al modello i token della query originale insieme ad attributi dell'utente, contesto temporale e, opzionalmente, risposte del sistema di ricerca a varianti precedenti.

> COSA RIVENDICA

Le rivendicazioni indipendenti (claim 1 e 14) coprono un metodo e un sistema che ricevono una query originale generata da input utente tramite client device e applicano a un modello generativo addestrato tre elementi: la posizione dell'utente (location), uno o più attributi dell'utente determinati in base a query submissions precedenti, e la query originale stessa. Il sistema genera un output generativo basato su questa applicazione, quindi applica ulteriore input al modello (basato sull'output generativo appena prodotto) per generare ulteriore output generativo. Infine, genera un output basato su quest'ultimo output generativo e lo fornisce al client device in risposta alla query originale.

Le rivendicazioni dipendenti aggiungono dettagli rilevanti. La claim 2 contempla l'applicazione al modello anche di contenuti recentemente visualizzati dall'utente sul client device. Le claim 3-5 e 8 coprono la selezione del modello generativo addestrato da una pluralità di modelli candidati, dove la selezione può basarsi sugli attributi utente (claim 4) o su un task attualmente svolto dall'utente (claim 5). Le claim 6-7, 9-10 e 19 specificano che l'ulteriore input può includere l'output generativo stesso (claim 6, 9) oppure ulteriori risposte del sistema di ricerca che sono responsive all'output generativo (claim 7, 10, 19). Le claim 11-13 dettagliano che la posizione dell'utente applicata al modello può includere una città (claim 11), uno stato (claim 12) o una regione (claim 13). Le rivendicazioni 14-20 replicano la struttura per un sistema anziché un metodo.

> LETTURA SEO (INTERPRETAZIONE)

La descrizione contempla un sistema di generazione varianti significativamente più articolato delle rivendicazioni. Il modello generativo descritto è tipicamente una rete neurale sequence-to-sequence con memory layer (LSTM o GRU), simile architetturalmente ai modelli di traduzione automatica neurale ma addestrato su dati specifici per varianti di query (paragrafi relativi a "sequence to sequence model" e "memory layers"). La descrizione contempla training basato su coppie di query con click sugli stessi documenti (per varianti equivalenti), coppie di query successive (per follow-up), e coppie query originale-canonica (per canonicalizzazione).

Il documento contempla modelli multitask addestrati per generare diversi tipi di varianti: equivalenti, follow-up, generalizzazioni, canonicalizzazioni, traduzioni linguistiche, entailment, specificazioni e chiarificazioni (sezione "multitask model"). Il tipo di variante da generare potrebbe essere indicato da un type value applicato come input al modello. La descrizione contempla anche l'addestramento di modelli separati per gruppi di utenti con attributi comuni o per task specifici (es. shopping online, viaggio verso una location), con selezione del modello appropriato a runtime in base agli attributi utente o al task predetto (sezioni su "multiple generative models").

Un aspetto rilevante è l'iterazione controllata: la descrizione contempla un control model separato (potenzialmente una rete feedforward o RNN) che agisce come "critic" mentre il generative model è l'"actor" in un ambiente actor-critic (sezione "control model" e FIG. 4). Il control model riceverebbe come input feature dello stato corrente (query originale, varianti già generate, risposte del search system) e determinerebbe se generare ulteriori varianti o fermarsi. La descrizione contempla training tramite reinforcement learning dove le reward sono proporzionali alla qualità delle risposte fornite dal search system, con approccio Monte-Carlo Q-learning (sezione "reinforcement learning").

Per la SEO, questo brevetto potrebbe indicare che Google esplora internamente varianti di una query per verificare, arricchire o sostituire i risultati della query originale. Le varianti follow-up potrebbero servire a verificare la correttezza di una risposta (esempio in FIG. 8B: query "did michelangelo paint the mona lisa" genera risposta "yes" ma varianti follow-up non trovano conferme, quindi viene fornito "no"). Le varianti equivalenti o di generalizzazione potrebbero servire a trovare risultati quando la query originale non ne produce. La personalizzazione tramite attributi utente (location, task, contenuti recentemente visualizzati) suggerirebbe che query identiche di utenti diversi potrebbero essere elaborate diversamente. Tuttavia, la complessità del sistema descritto (iterazioni multiple, control model, reinforcement learning con interazione live col search system) renderebbe l'implementazione in produzione computazionalmente costosa, specialmente per query ad alto volume.

> COSA NON DIMOSTRA

  • Si tratta di una domanda di brevetto (A1), non ancora concessa, e fa parte di una famiglia con continuation (US12579133B2), quindi non rappresenta protezione indipendente.
  • Il brevetto non dimostra che Google utilizzi questo sistema in produzione per Search. La complessità computazionale descritta (iterazioni multiple con chiamate al search system, control model separato, reinforcement learning) suggerirebbe costi elevati per deployment su larga scala.
  • Non specifica quali segnali di ranking vengano utilizzati dal search system per valutare le risposte alle varianti, né come le risposte alle varianti influenzino concretamente il ranking dei risultati mostrati all'utente.
  • La descrizione contempla utilizzi anche per advertising (fornire ads assegnati a varianti generate) e per utenti con difficoltà di formulazione query, ambiti che esulano dal ranking organico tradizionale.

> COSA FARE COMUNQUE

  1. Assicurarsi che i contenuti rispondano non solo alla query letterale ma anche a varianti semanticamente correlate (riformulazioni, follow-up naturali, generalizzazioni) per massimizzare la copertura tematica.
  2. Considerare che query apparentemente identiche potrebbero essere elaborate diversamente in base al contesto utente (location, dispositivo, cronologia), quindi testare le SERP in condizioni diverse quando possibile.
  3. Per contenuti che forniscono risposte dirette, verificare la coerenza delle informazioni con possibili domande di approfondimento o verifica, poiché risposte contraddittorie a query correlate potrebbero segnalare inaffidabilità.
  4. Prestare attenzione alla struttura informativa dei contenuti in modo che rispondano a intent multipli correlati, non solo alla keyword target isolata, facilitando il recupero per varianti semantiche della query.
