> BREVETTO CONCESSO · US8700639B1

Aggiustamento del ranking basato su percorsi di query

Titolo originale: Rank-adjusted content items

Il brevetto affronta il problema di identificare contenuti rilevanti per l'utente considerando il contesto della sessione di ricerca, non solo la singola query. Il sistema analizza i log storici per identificare percorsi di query ricorrenti (sequenze di ricerche che portano alla selezione di determinati contenuti) e adatta il ranking dei risultati quando la sessione corrente corrisponde a uno di questi percorsi.

> COSA RIVENDICA

La rivendicazione indipendente 1 protegge un metodo che identifica "query paths" da sessioni di ricerca precedenti, dove ogni query path definisce un contesto ed è costituito da una pluralità di query nell'ordine in cui sono state fornite. Il metodo identifica le query della sessione corrente, le confronta con i query paths storici e determina che il contesto della sessione corrente è correlato a un query path precedente quando due o più query del path storico sono simili a due o più query della sessione corrente.

La rivendicazione 2 specifica che la determinazione di similarità comprende l'identificazione di una "union" (unione) tra le query del path storico e quelle della sessione corrente. La rivendicazione 3 aggiunge che il contesto è correlato al query path se l'unione identificata è una "exclusive union" (unione esclusiva), quindi senza query estranee al path.

Le rivendicazioni 4 e 5 coprono l'applicazione pratica: identificare contenuti responsivi a una query della sessione corrente basandosi sulla determinazione del contesto (rivendicazione 4) e aggiustare il ranking di un contenuto responsivo alla query in base a questa determinazione (rivendicazione 5).

La rivendicazione 6 specifica che l'identificazione dei query paths comprende l'analisi di "click log and query log data" per identificare set simili o identici di query da sessioni precedenti durante le quali è avvenuta anche la presentazione di uno stesso contenuto. La rivendicazione 7 precisa che questo contenuto può essere una pagina web.

Le rivendicazioni da 8 a 20 replicano la stessa struttura in forma di "computer-readable storage medium" (rivendicazioni 8-14) e "system" (rivendicazioni 15-20), senza aggiungere elementi sostanziali diversi dal metodo.

> LETTURA SEO (INTERPRETAZIONE)

La descrizione contempla il concetto di "content terminus" (paragrafi relativi a FIG. 1 e FIG. 2), definito come il termine di un query path che corrisponde alla selezione finale di un contenuto. Un content terminus può essere un singolo content item (ad esempio un URL) o un nodo che associa uno o più query paths con uno o più content items. La descrizione indica che i query paths possono essere identificati analizzando click log e query log per trovare set di query simili o identici forniti da un numero statisticamente significativo di utenti che hanno poi selezionato lo stesso contenuto (paragrafo relativo a rivendicazione 6).

La descrizione contempla diversi criteri di matching tra sessione corrente e query paths storici. In un'implementazione, una sessione è correlata a un query path solo se tutte le query della sessione definiscono una "exclusive union" con il path, escludendo quindi sessioni con query estranee (esempio con Q11, Q18, Q13 in FIG. 3). In un'altra implementazione, è sufficiente che alcune query della sessione siano in comune con il path (esempio con Q11, Q18, Q12 in FIG. 3).

La descrizione contempla aggiustamenti di ranking proporzionali alla probabilità di selezione: se il 55% delle sessioni con un certo contesto ha selezionato BERRYURL1 e il 35% BERRYURL2, questi contenuti potrebbero essere rankati primo e secondo rispettivamente (paragrafo relativo a FIG. 1). La FIG. 5 mostra esempi concreti dove il ranking di contenuti C1 e C2 passa da posizioni 237 e 331 (senza contesto) a posizioni 1 e 2 quando il contesto della sessione corrisponde al query path.

La descrizione contempla anche la riduzione del ranking: un contenuto normalmente rankato primo per query isolate potrebbe essere declassato se raramente selezionato nel contesto di un query path specifico (paragrafo in FIG. 1). Contempla inoltre l'identificazione di categorie per query paths e sessioni, permettendo aggiustamenti basati su categorie anche quando non c'è corrispondenza diretta tra i termini (FIG. 11, esempio fruit category).

Per la SEO, questo potrebbe significare che la rilevanza di una pagina non dipenderebbe solo dall'ottimizzazione per singole keyword, ma dalla sua capacità di soddisfare utenti in specifici percorsi di ricerca. Se storicamente gli utenti che cercano A, poi B, poi C selezionano la pagina X, questa potrebbe rankare meglio per la query C quando preceduta da A e B. Tuttavia, il brevetto non specifica soglie di significatività statistica né pesi relativi del contesto rispetto ad altri fattori di ranking.

> COSA NON DIMOSTRA

  • Non specifica quali soglie quantitative definiscano un numero "statisticamente significativo" di utenti né come i segnali contestuali siano pesati rispetto ad altri fattori di ranking.

> COSA FARE COMUNQUE

  1. Progettare contenuti che rispondano a intenti di ricerca progressivi, non solo a singole keyword isolate, considerando i percorsi informativi tipici degli utenti nel proprio settore.
  2. Analizzare i propri dati analytics per identificare sequenze ricorrenti di landing page e ottimizzare i contenuti per supportare questi percorsi, indipendentemente dal fatto che Google usi questo specifico brevetto.
  3. Considerare che la rilevanza contestuale potrebbe premiare contenuti che soddisfano utenti in fasi specifiche di un percorso informativo, anche se non ottimizzati per il massimo volume di una singola keyword.
  4. Monitorare le variazioni di posizionamento per le stesse query in momenti diversi, che potrebbero indicare l'applicazione di segnali contestuali o di sessione.

> TERMINI CHIAVE

query path
Sequenza di query in un ordine specifico fornite durante una sessione di ricerca precedente, che definisce un contesto
content terminus
Termine di un query path che corrisponde alla selezione finale di un contenuto, può essere un singolo URL o un nodo che associa più query paths a più contenuti
exclusive union
Unione tra le query della sessione corrente e quelle di un query path storico che non include query estranee al path
search session context
Contesto definito dalle query multiple di una particolare sessione di ricerca, utilizzato per determinare la correlazione con query paths storici
selection distribution
Distribuzione percentuale delle selezioni di diversi contenuti da parte di utenti che hanno seguito un determinato query path
