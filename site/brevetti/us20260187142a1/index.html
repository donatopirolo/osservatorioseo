Sessioni di risposta live con domande di chiarimento

Titolo originale: System and Methods for Providing a Live Query Response Session

Il brevetto descrive un sistema per condurre sessioni di risposta live a query multimodali (testo, audio, video). Un modello di orchestrazione analizza la query, determina se servono informazioni aggiuntive e, se necessario, pone domande di chiarimento all'utente in tempo reale o esegue ricerche web prima di generare una risposta tramite un modello di elaborazione sequenziale.

> COSA RIVENDICA

La rivendicazione indipendente 1 copre un metodo per fornire una sessione di risposta live. Il sistema avvia una sessione con un dispositivo utente e riceve una query multimodale che include contenuto video. Un modello di orchestrazione determina uno o più passaggi di recupero informazioni per acquisire informazioni aggiuntive associate alla query multimodale, dove questi passaggi includono una domanda di chiarimento che richiede informazioni aggiuntive all'utente. Il sistema fornisce la domanda di chiarimento al dispositivo utente, riceve la risposta dell'utente in tempo reale, genera un input per il modello basato sulla query multimodale e sulla risposta utente, elabora questo input con un modello di risposta per generare un output, e trasmette l'output al dispositivo utente. Il metodo include anche la ricezione di contenuto audio dal dispositivo utente e la determinazione che tale audio contiene feedback dell'utente rispetto alla query multimodale.

La rivendicazione 2 specifica che determinare i passaggi di recupero informazioni comprende identificare uno o più pezzi di dati mancanti dalla query multimodale necessari per generare un output del modello. La rivendicazione 3 definisce i tipi di dati come user specific data, query specific data e web query data. La rivendicazione 4 stabilisce che se un pezzo di dati ha tipo web query, il sistema genera ed esegue una query di ricerca per recuperare il dato da un database di ricerca web. La rivendicazione 5 prevede che se un dato ha tipo user specific o query specific, il sistema genera una query di chiarimento e la trasmette al dispositivo utente.

Le rivendicazioni 6-8 riguardano l'analisi del contenuto video: il sistema analizza i dati video per determinare caratteristiche delle immagini per ciascun frame (chiarezza, messa a fuoco, posizione e orientamento della camera) e determina le porzioni rilevanti del video basandosi su queste caratteristiche. La rivendicazione 9 specifica che la query multimodale può includere contenuto testuale o vocale. Le rivendicazioni 10-12 descrivono che il modello di orchestrazione determina una pluralità di passaggi di elaborazione rappresentati come istruzioni computazionali, traccia lo stato corrente del processo di risposta e aggiorna tale stato dopo ogni passaggio completato.

La rivendicazione 13 stabilisce che l'output del modello può comprendere immagini visive e contenuto audio, formattato per far sì che il dispositivo utente visualizzi le immagini mentre presenta l'audio. La rivendicazione 14 specifica che le immagini visive possono contenere contenuto diverso da quello presentato nell'audio. Le rivendicazioni 16-18 coprono il monitoraggio continuo dell'input utente: mentre presenta l'output del modello, il sistema riceve dati audio catturati dal sensore audio del dispositivo utente, analizza se l'audio rappresenta input vocale rilevante per la query multimodale, e se determinato rilevante, aggiorna l'input del modello per includere questo ulteriore feedback e può interrompere la presentazione dell'output corrente.

> LETTURA SEO (INTERPRETAZIONE)

La descrizione contempla un sistema di orchestrazione che coordina l'interazione conversazionale tra utente e modello. Il sistema può determinare se una query multimodale contiene informazioni sufficienti per generare una risposta adeguata utilizzando un modello di classificazione che genera un punteggio di confidenza o analizzando se una risposta provvisoria coprirebbe tutti i topic attesi. Se le informazioni sono insufficienti, un planning model determina il tipo di dati mancanti tra tre categorie: user specific data (preferenze, esperienze, storia dell'utente), query specific data (contesto specifico della query, informazioni su oggetti o luoghi raffigurati), e web query data (informazioni specialistiche recuperabili tramite ricerca web).

Il sistema contempla l'analisi dei frame video basata su caratteristiche delle immagini come clarity, focus, e informazioni sulla posizione e orientamento della camera al momento della cattura, per determinare quali porzioni del video sono rilevanti e quali possono essere scartate come rumore. La descrizione menziona che il modello di orchestrazione può essere tuned per porre più o meno domande di chiarimento in base alle preferenze dell'utente: alcuni utenti potrebbero preferire meno interruzioni, altri potrebbero trovare le domande di chiarimento utili.

L'output del modello può essere multimodale con componenti visive e audio sincronizzate ma con contenuto diverso: le componenti visive possono includere diagrammi ed esempi, mentre l'audio può fornire spiegazioni di ciò che è visualizzato, con evidenziazione o sottolineatura delle porzioni rilevanti del display quando l'audio le discute. Il sistema contempla dati di sincronizzazione che permettono di coordinare la presentazione di audio e video al momento appropriato.
