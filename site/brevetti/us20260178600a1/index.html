> DOMANDA DI BREVETTO · US20260178600A1

Organizzazione dinamica dei risultati per temi tramite modello generativo

Titolo originale: Dynamic organization of search results

Il brevetto descrive un sistema che usa un modello generativo (dynamic result model) per rispondere a una query utente generando più topic object, ciascuno dei quali accoppia una query raffinata (topic query) a un servizio di ricerca tematico specializzato (places, video, forum, ricette, ecc.). Il sistema ottiene risultati da questi servizi e li organizza in rich result listing nella pagina dei risultati.

> COSA RIVENDICA

La rivendicazione indipendente 1 copre un metodo che, in risposta a una user query, fornisce la query e attributi sulla query come input a un modello generativo addestrato a generare una pluralità di topic object. Ogni topic object accoppia una topic query con un topical search service. Per ciascun topic object in un sottoinsieme della pluralità, il metodo ottiene rispettivi search results inviando la topic query al topical search service corrispondente. Infine, fornisce una search result page che include rich result listing per i rispettivi search results dei topic object nel sottoinsieme.

Le rivendicazioni dipendenti aggiungono dettagli rilevanti. La rivendicazione 2 specifica che il topic object può includere un title generato per la topic query, visualizzato come parte del rich result listing. La rivendicazione 3 contempla che almeno un topic object possa includere una short description relativa alla topic query, visualizzata nel rich result listing. La rivendicazione 4 prevede che almeno un topic object possa includere una justification relativa alla topic query, anch'essa visualizzata. La rivendicazione 5 indica che gli attributi della query possono includere interessi da un profilo associato all'utente che fornisce la query. La rivendicazione 6 copre l'emissione concorrente delle topic query ai rispettivi topical search service. La rivendicazione 7 specifica l'ordinamento dei search results nella search result page secondo l'ordine in cui i topic object sono stati forniti dal modello generativo. La rivendicazione 8 copre la determinazione di un confidence score generato dal modello generativo per ciascun topic object e la selezione dei topic object per il sottoinsieme in base al confidence score che soddisfa una soglia predeterminata. La rivendicazione 9 riguarda il ricevere una selezione di un search result associato a un particolare topic object e il raffinamento del modello generativo usando il search result, la user query e gli attributi sulla query nel reinforcement learning. La rivendicazione 10 copre la determinazione che la user query soddisfa una popularity threshold e il salvataggio dei rich result listing come pre-computed listing per la query. La rivendicazione 11 estende questo concetto a una seconda query che corrisponde alla prima, fornendo una seconda search result page che include il pre-computed listing. Le rivendicazioni 12 e 20 coprono rispettivamente un sistema e un mezzo non transitorio che implementano il metodo descritto.

> LETTURA SEO (INTERPRETAZIONE)

La descrizione contempla che il dynamic result model sia un modello generativo basato su architettura transformer, addestrato per il compito specifico di generare topic object data una user query e attributi sulla query (paragrafi che descrivono il modello). Gli attributi della query possono includere ora del giorno, indicazione di prossimità a festività o eventi, informazioni meteo, localizzazione generalizzata e, con permesso utente, cronologia delle query e preferenze dell'utente (paragrafi su query features 210). La descrizione contempla che il modello possa essere addestrato con meno di 100 esempi, in alcuni casi meno di 50, che mostrano come funzionano diversi topical search service (paragrafo sull'addestramento del modello).

I topic object generati includono un type che identifica il topical search service e una topic query raffinata per quel servizio (paragrafi su topic objects 240). La descrizione contempla che il modello possa generare più topic object dello stesso tipo ma con topic query diverse, aumentando la diversità dei risultati (esempio con due places type). Ogni topic object può includere un title, una short description e/o una justification, tutti generati dal modello (descrizione dei componenti del topic object). La descrizione contempla esempi di topical search service come places, video, restaurant, recipe, forums, events (paragrafi sui topical search services 150).

La descrizione contempla che il sistema possa filtrare topic object che non soddisfano criteri di rilevanza, come un confidence score sotto una soglia predeterminata o una similarity measure con la user query sotto una similarity threshold (step 402 di FIG. 4). La descrizione contempla l'emissione concorrente delle topic query per ridurre la latenza (step 404) e la possibilità di fornire rich result listing iniziali entro un tempo limite specificato, aggiornando la pagina successivamente con risultati arrivati dopo (step 412, clause 8).

Per la SEO, questo potrebbe significare che query aperte o con intento ambiguo potrebbero attivare questo sistema, generando rich result listing tematici che occupano spazio nella SERP. Le risorse potrebbero apparire in questi listing se sono indicizzate dai topical search service rilevanti e se rispondono alle topic query raffinate generate dal modello. Il sistema potrebbe favorire risultati diversificati che coprono aspetti multipli della query originale, potenzialmente riducendo la visibilità di risultati organici tradizionali. La personalizzazione basata su attributi della query e, con permesso, del profilo utente, potrebbe significare che gli stessi contenuti appaiono in modi diversi per utenti diversi. Il reinforcement learning basato su selezioni utente potrebbe progressivamente ottimizzare quali topic object e quali topical search service vengono privilegiati per determinate query.

Tuttavia, la descrizione non specifica quali segnali di ranking usano i singoli topical search service per ordinare i propri risultati. Non è chiaro quali tipi di query attiverebbero questo sistema rispetto al sistema convenzionale. La descrizione contempla che query fattuali potrebbero non usare il dynamic result model (paragrafo su step 302), ma non definisce precisamente il confine.

> COSA FARE COMUNQUE

  1. Assicurarsi che i contenuti siano indicizzabili e accessibili ai servizi di ricerca tematici rilevanti per il proprio settore (places, video, forum, ricette, eventi, ecc.), non solo al crawl web generale.
  2. Per query che coprono aspetti multipli o intenti sfumati, considerare la creazione di contenuti che rispondano a sotto-aspetti specifici e chiaramente definiti, facilitando il matching con topic query raffinate.
  3. Monitorare la SERP per query rilevanti al proprio business per identificare quali rich result listing tematici appaiono e quali servizi vengono privilegiati, adattando la strategia di presenza su quei canali.
  4. Mantenere coerenza e completezza delle informazioni strutturate e dei metadati che i topical search service utilizzano, poiché questi potrebbero diventare fonti primarie per rich result listing generati dinamicamente.
