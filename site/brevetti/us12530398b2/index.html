> BREVETTO CONCESSO · US12530398B2

Citazioni visive per risposte a query multimodali

Titolo originale: Visual citations for information provided in response to multimodal queries

Il brevetto affronta il problema di fornire risposte a query multimodali (immagine + prompt testuale) con la possibilità di verificarne l'accuratezza. Il sistema recupera immagini visivamente simili alla query image, estrae testo dai documenti che le contengono, genera una risposta al prompt elaborando il testo estratto con un modello linguistico, e presenta la risposta insieme alle immagini come "citazioni visive" che permettono all'utente di valutare rapidamente la pertinenza delle fonti.

> COSA RIVENDICA

La rivendicazione indipendente 1 protegge un metodo che recupera una result image in base alla similarità con una query image, ottiene una prima unità di testo da un documento sorgente che include la result image, riceve un prompt associato alla query image, determina una seconda unità di testo elaborando la prima unità di testo e il prompt con un modello linguistico machine-learned (la seconda unità può includere testo derivato dalla prima), genera attribution information che include un link associato alla result image elaborando la seconda unità di testo e la result image, e fornisce per la visualizzazione l'attribution information, la seconda unità di testo e la result image.

La rivendicazione 2 specifica che il recupero avviene elaborando la query image con un modello di visual search per ottenere una rappresentazione intermedia e recuperando la result image in base alla similarità tra le rappresentazioni intermedie. La rivendicazione 3 dettaglia che il modello può essere un embedding model e il recupero basato sulla distanza tra embeddings in uno spazio di embedding. Le rivendicazioni 4-7 coprono l'ottenimento della query image da un dispositivo utente e la ricezione del prompt prima o dopo la fornitura della result image. La rivendicazione 8 specifica che il documento sorgente può essere pagine web, articoli, giornali, libri o trascrizioni. Le rivendicazioni 9-11 coprono l'attribution information che identifica il documento o indica dove accedervi (URL per pagine web, citazione per riviste). Le rivendicazioni 12-13 coprono la generazione automatica del prompt elaborando la query image con un modello per ottenere un output semantico. Le rivendicazioni 14-16 coprono tecniche per selezionare porzioni di testo dal documento: uso di euristiche, selezione di testo che precede o segue l'immagine nel documento, o uso di un modello di classificazione.

La rivendicazione indipendente 17 copre un sistema che ottiene query image e prompt da un dispositivo utente, elabora la query image con un embedding model, recupera result image, identifica il documento sorgente, determina la prima unità di testo, elabora prima unità e prompt con un modello linguistico per ottenere la seconda unità, genera attribution information elaborando seconda unità e result image, e fornisce tutto per la visualizzazione. La rivendicazione 18 copre il raffinamento iterativo: ricezione di richiesta di informazioni aggiuntive, recupero di seconda result image, identificazione di più documenti sorgente per la stessa immagine con contenuto testuale diverso, elaborazione di unità di testo aggiuntive. La rivendicazione 20 copre il caso di più result images con elaborazione di un set di input testuali che include unità di testo da due o più result images e il prompt, generando attribution information elaborando la seconda unità di testo e la result image, e fornendo attribution information, seconda unità e le immagini.

> LETTURA SEO (INTERPRETAZIONE)

La descrizione contempla un flusso in cui un visual search computing system riceve una multimodal query (query image 206 e prompt 208) da un dispositivo utente. Se il prompt non è fornito, il sistema può generarlo elaborando la query image con un modello semantico (blocco 210, claim 13). L'image evaluation module 210 elabora la query image con un visual search model 214 (tipicamente un embedding model) per generare una rappresentazione intermedia e seleziona result images 212 da un image search space 215 (embedding space) in base alla distanza (blocco 210, FIG. 2).

Il document content selection module 218 recupera documenti 220 che includono le result images tramite document indexing information 216. La descrizione contempla diverse tecniche per estrarre la prima unità di testo 224 dal documento: selezione euristica di testo che precede o segue l'immagine (claim 15, esempio del sito per speed boat enthusiast), selezione di tutto il testo se il documento è breve, o uso di un modello di classificazione (claim 16). Il documento può essere un sito web, articolo accademico, libro, trascrizione (claim 8, blocco 220).

Il text determination module 226 elabora la prima unità di testo 224 e il prompt 208 con un machine-learned language model 230 (descritto come large language model addestrato su ampio corpus, potenzialmente ottimizzato per task specifici, blocco 226) per generare la seconda unità di testo 228. La descrizione specifica che questa può essere una summarization (embodiment 32), può includere parte del testo originale o testo derivato (claim 1), e può includere predictive information che identifica la porzione più rilevante per il prompt (embodiment 30, emphasis element 506 in FIG. 5A).

L'interface data generation module 232 genera interface data 234 che include la seconda unità di testo, le result images e attribution information 236 (titolo, autore, URL, citazione bibliografica a seconda del tipo di documento, claims 9-11). La descrizione contempla diverse modalità di presentazione: primary interface element 404 con risposta diretta e attribution element 405 (FIG. 4), o interface element 504 con contesto e emphasis element 506 che evidenzia la porzione rilevante (FIG. 5A). La scelta del formato potrebbe dipendere dalla certezza dell'informazione o dalla comprensione semantica del prompt ("good plane" è soggettivo, quindi viene fornito contesto, blocco tra FIG. 5A e 6A).

La descrizione contempla raffinamento iterativo basato su feedback utente (FIGS. 6A-7B): l'utente può selezionare un attribution element 704B per indicare che una result image 612B non è pertinente (input 706, FIG. 7A). Il sistema riceve result image selection information 628, rimuove le unità di testo associate al documento di quella immagine dal set di input, rielabora il set ridotto con il language model per generare una seconda unità di testo raffinata 630 (FIG. 6B, claims 28-29). La descrizione contempla anche la rimozione dell'attribution information associata (claim 29).

Per la SEO, questo potrebbe significare che in contesti di ricerca multimodale con risposte generate, la pertinenza visiva tra immagini presenti in un documento e l'oggetto della query potrebbe condizionare l'estrazione e l'utilizzo del testo del documento per generare risposte. Un documento con immagini visivamente coerenti con la query image avrebbe maggiori probabilità di vedere il proprio testo utilizzato. L'attribution tramite link e thumbnail potrebbe rappresentare una forma di visibilità, anche se subordinata alla risposta generata. Il meccanismo di feedback negativo contemplato suggerirebbe che segnali di incoerenza visiva potrebbero ridurre il peso di un documento nelle iterazioni successive. Tuttavia, la descrizione non specifica criteri di ranking tra documenti né segnali di qualità del testo oltre alla prossimità all'immagine nel documento.

> COSA NON DIMOSTRA

  • Il brevetto non dimostra che questo sistema sia attivo in Google Search o in altri prodotti. È una domanda concessa, ma l'implementazione resta non verificabile.
  • Non specifica criteri di ranking tra documenti sorgente quando più documenti contengono la stessa result image, né pesi assegnati a diversi segnali (qualità del testo, autorevolezza del documento, freschezza).
  • La selezione del testo dal documento è descritta con tecniche euristiche o modelli di classificazione non dettagliati: non è chiaro quali porzioni di un documento lungo vengano effettivamente utilizzate né con quale priorità.
  • Il brevetto copre query multimodali (immagine + testo), non la ricerca testuale tradizionale: l'applicabilità a scenari SEO classici è indiretta e condizionata all'adozione di interfacce multimodali.

> COSA FARE COMUNQUE

  1. Assicurarsi che le immagini presenti in un documento siano coerenti e pertinenti al contenuto testuale circostante: la prossimità testo-immagine è contemplata come criterio di selezione.
  2. Mantenere una struttura documentale chiara in cui il testo rilevante sia posizionato vicino alle immagini correlate, facilitando l'estrazione automatica di contesto pertinente.
  3. Fornire metadati accurati e attribution information chiara (titoli, autori, URL stabili) per documenti e immagini, poiché queste informazioni sono contemplate per l'identificazione delle fonti.
  4. Considerare che in scenari di ricerca multimodale, la qualità e la pertinenza visiva delle immagini potrebbero influenzare indirettamente la visibilità del contenuto testuale associato, anche senza modifiche al ranking tradizionale.
