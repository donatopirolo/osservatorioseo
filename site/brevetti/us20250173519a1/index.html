> DOMANDA DI BREVETTO · US20250173519A1

Comprensione dell'intento e riscrittura di query conversazionali

Titolo originale: Query Intent Understanding and Search Result Generation

Il brevetto affronta la difficoltà di determinare l'intento di query in sessioni chat multi-turno, dove i messaggi dipendono dal contesto precedente. Utilizza un modello linguistico generativo per riscrivere la query corrente includendo dettagli dal contesto della sessione, poi mappa la query riscritta a cluster di embedding associati a intenti simili tramite un grafo di intenti, per determinare risultati di ricerca pertinenti.

> COSA RIVENDICA

Le rivendicazioni indipendenti (1, 10, 14) coprono tre metodi distinti. La rivendicazione 1 descrive un metodo per generare una query contestualmente consapevole: si ottiene una query di input e dati multi-turno (messaggi precedenti della stessa sessione), si processano insieme per generare una "contextually aware query" che include dettagli aggiuntivi dal contesto multi-turno, si processa questa query con un modello di embedding per generare un query embedding, si determina un cluster di query embedding associato (contenente embedding di altre query simili), e si determinano risultati di ricerca basati sul cluster. La rivendicazione 2 specifica che il modello di embedding può essere addestrato per mappare query con intenti simili allo stesso cluster. La rivendicazione 3 aggiunge la determinazione di attributi del query embedding (descrittivi di topic particolari). La rivendicazione 4 introduce la coppia query-intent, dove il query embedding è associato sia alla query contestuale che a un intento. La rivendicazione 5 descrive il mapping della coppia query-intent a uno spazio di embedding e l'associazione con un nodo in un query graph. La rivendicazione 6 definisce il cluster come parte di un "learned intent graph" con nodi (cluster di query con intenti correlati) ed edge (collegamenti tra nodi con intenti correlati). Le rivendicazioni 7-9 aggiungono: determinazione di media content items (7), supporto per dati multimodali nell'input query (8-9, inclusi immagini e testo). La rivendicazione 10 copre un sistema che implementa metodo simile ma specifica l'uso di un "machine-learned language model" per generare la "multi-turn aware query" processando input query e dati multi-turno. Le rivendicazioni 11-13 aggiungono: il language model può essere un modello generativo pre-addestrato su contenuti diversi (11), il cluster può essere associato a un nodo in un task graph (12), il cluster include query con attributi condivisi legati agli intenti (13). La rivendicazione 14 copre un metodo di training: si processa una query con un embedding model per generare query embedding, si processa con un generative model per determinare query intent, si ottengono embedding di altre query con intenti simili, si valuta una loss function confrontando il query embedding con gli altri embedding, si aggiustano parametri dell'embedding model. Le rivendicazioni 15-20 aggiungono dettagli sul training: la query può essere riscritta da input query e dati multi-turno (15), gli embedding possono provenire da cluster in un data graph (16), può includere determinazione di intent embedding (17), intenti associati a topic particolari (18), generazione di data graph rimodellato (19), con edge per topic tangenziali (20).

> LETTURA SEO (INTERPRETAZIONE)

La descrizione contempla un sistema che utilizza modelli linguistici generativi (LLM, blocco 206) per processare query da interfacce chat-style dove i messaggi dipendono da input precedenti. L'esempio fornito (blocco 402-408, FIG. 4) mostra una query "How much does it cost?" riscritta in "How much does the new smartphone cost?" dopo aver processato la cronologia della sessione che menzionava "new smartphone". La descrizione specifica che il generative model può essere pre-addestrato su molteplici task di natural language processing e può processare dati multimodali inclusi immagini e testo. Il query embedding model (blocco 306) mappa le query a uno spazio di embedding associato a un intent graph (blocco 308), descritto come struttura con nodi rappresentanti cluster di query con intenti correlati ed edge che collegano cluster con intenti o attributi simili (FIG. 5, blocco 510-512). La descrizione contempla training del query embedding model tramite due pipeline (FIG. 6): una confronta embedding di query simili (blocco 612), l'altra usa intent determination da un generative model per valutare loss function (blocco 630) e addestrare il modello a generare embedding simili per query e rispettivi intenti. La descrizione menziona determinazione di attributi degli intenti (FIG. 7, blocco 704) come "commercial intent", "consumer-facing", "late-stage funnel", o "niche question", che potrebbero essere utilizzati per targeting di content item. Gli edge del grafo potrebbero suggerire "next steps" (es. da ricerca prezzo a ricerca garanzia). La descrizione specifica che content item possono essere taggati e indicizzati in associazione con particolari cluster o nodi per surfacing uniforme. Per la SEO, questo potrebbe significare che in contesti conversazionali Google potrebbe riscrivere query ambigue aggiungendo contesto dalla sessione, mappare la query riscritta a cluster di intenti appresi, e determinare risultati basandosi su query simili già comprese nel cluster. I risultati potrebbero essere influenzati da attributi commerciali degli intenti determinati. Tuttavia, la descrizione non specifica quali segnali di ranking vengano applicati né come i content item vengano effettivamente selezionati oltre al mapping a cluster. Il sistema potrebbe favorire contenuti pre-indicizzati per specifici cluster di intenti, ma questo resta speculativo. L'approccio basato su cluster potrebbe ridurre la dipendenza da matching esatto di termini, spostando il focus verso comprensione semantica dell'intento attraverso sessioni multi-turno.

> COSA FARE COMUNQUE

  1. Per contenuti destinati a contesti conversazionali (assistenti, chat), strutturare informazioni in modo che rispondano a intenti completi piuttosto che solo a frammenti di query isolati potrebbe migliorare la pertinenza.
  2. Considerare che query ambigue in sessioni conversazionali potrebbero essere interpretate con contesto aggiunto automaticamente, quindi contenuti che rispondono a intenti più ampi e dettagliati mantengono valore.
  3. Documentare chiaramente topic e intenti principali dei contenuti può facilitare associazioni semantiche indipendentemente dai meccanismi di clustering specifici.
  4. Monitorare come le query degli utenti evolvono in sessioni multi-turno può informare la creazione di contenuti che anticipano progressioni naturali di intenti (es. da informazioni generali a dettagli d'acquisto).
