Recupero di documenti rilevanti tramite token vettoriali contestualizzati

Titolo originale: Contextualized token retriever

Il brevetto descrive un metodo per identificare documenti rilevanti rispetto a una query utilizzando solo un sottoinsieme recuperato di token vettoriali dei documenti candidati, anziché tutti i token vettoriali del documento. Query e documenti vengono processati da reti neurali encoder per generare token vettoriali; per ogni token della query si identificano i token documentali più simili, si selezionano documenti candidati e si calcola un punteggio di rilevanza usando solo i token documentali già recuperati, con valori imputati per i token mancanti.

> COSA RIVENDICA

La rivendicazione indipendente 21 copre un metodo per identificare in modo efficiente documenti rilevanti rispetto a una query. Il sistema mantiene dati che associano ciascun documento a una pluralità di document token vectors che lo rappresentano. Ricevuta la query, la processa con un query encoder neural network per generare una pluralità di query token vectors. Per ciascun query token vector, identifica un insieme di document token vectors più simili secondo una misura di similarità. Identifica quindi un insieme di candidate documents che include ogni documento rappresentato da uno o più document token vectors provenienti dagli insiemi identificati per i query token vectors. Per ciascun candidate document, genera un relevance score identificando un retrieved subset di document token vectors del candidato, ovvero quelli inclusi negli insiemi più simili ai query token vectors, dove il retrieved subset contiene meno di tutti i document token vectors del documento. Determina uno o più query scores basati su valori di similarità tra il retrieved subset e i corrispondenti query token vectors, combina i query scores per generare il relevance score, seleziona come documenti rilevanti un sottoinsieme dei candidati usando i relevance scores e fornisce in risposta dati che identificano i documenti rilevanti.

Le rivendicazioni dipendenti aggiungono dettagli operativi. La rivendicazione 22 specifica che ogni documento viene processato da un document encoder neural network per generare i document token vectors. La rivendicazione 23 contempla che query encoder e document encoder possano essere la stessa rete neurale. La rivendicazione 24 definisce che determinare i query scores comporta impostare il query score per un dato query token vector al greatest similarity measure value tra quel query token e qualsiasi document token vector nel retrieved subset più simile. Le rivendicazioni 25-26 coprono il caso in cui un particolare query token vector non abbia un corrispondente document token vector nel retrieved subset: il query score viene impostato a un imputed value, che può essere il least similarity measure value tra quel query token e qualsiasi document token vector più simile. La rivendicazione 27 specifica che la misura di similarità può essere la cosine similarity. La rivendicazione 28 definisce che combinare i query scores comporta sommarli e dividere per il numero di query scores. La rivendicazione 29 copre la selezione dei candidati con i largest relevance scores. La rivendicazione 30 copre il processo di training con training batches contenenti training query e training documents, usando un objective function sui relevance scores. Le rivendicazioni 35-40 replicano il metodo come sistema e come storage media.

> COSA FARE COMUNQUE

  1. Strutturare i contenuti in modo che informazioni rilevanti siano distribuite in passaggi semanticamente densi e auto-contenuti, facilitando il matching token-level anche con sottoinsiemi ridotti di rappresentazioni.
  2. Mantenere coerenza semantica tra titoli, sottotitoli e corpo del testo: se il sistema confronta token vettoriali di query e documento, la ripetizione di concetti chiave in posizioni diverse aumenta la probabilità che token documentali rilevanti rientrino nei retrieved subsets.
  3. Evitare contenuti eccessivamente frammentati o con informazioni sparse: documenti con pochi token semanticamente rilevanti potrebbero generare relevance scores basati su imputed values, riducendo la competitività rispetto a documenti più densi.
  4. Considerare che sistemi di recupero basati su token vettoriali potrebbero favorire contenuti che rispondono direttamente a domande o richieste esplicite, come suggerito dagli esempi di query nella descrizione (domande dirette, keyword specifiche).

> TERMINI CHIAVE

query token vectors
Rappresentazioni vettoriali (embeddings) dei token che compongono la query, generate da un query encoder neural network
document token vectors
Rappresentazioni vettoriali (embeddings) dei token che compongono un documento, generate da un document encoder neural network
retrieved subset
Sottoinsieme dei document token vectors di un documento candidato che sono stati identificati come più simili ai query token vectors, usato per calcolare il relevance score senza recuperare tutti i token del documento
query score
Punteggio calcolato per ciascun query token vector rispetto a un documento candidato, basato sulla massima similarità con i document token vectors nel retrieved subset o su un imputed value se nessun token è presente
imputed value
Valore assegnato al query score quando nessun document token vector del candidato è presente nel set di token più simili al query token vector, per evitare bias nei relevance scores durante inference
relevance score
Punteggio di rilevanza complessivo di un documento candidato rispetto alla query, ottenuto combinando (es. mediando) i query scores di tutti i query token vectors
similarity measure
Metrica usata per determinare quanto un document token vector sia simile a un query token vector, ad esempio cosine similarity o Euclidean distance
