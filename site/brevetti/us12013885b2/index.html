> BREVETTO CONCESSO · US12013885B2

Canonicalizzazione delle query in domande in linguaggio naturale

Titolo originale: Canonicalizing search queries to natural language questions

Il brevetto descrive un sistema che determina se una query di ricerca è ben formata (grammaticale, esplicita, senza errori) e, in caso negativo, genera una variante ben formata utilizzando modelli di machine learning. Un modello di classificazione valuta la well-formedness, un modello di canonicalizzazione (sequence-to-sequence) genera la variante corretta.

> COSA RIVENDICA

La rivendicazione indipendente 1 descrive un metodo che determina una query correlata per una query data basandosi su dati storici di prossimità temporale delle sottomissioni. Genera una variante ben formata della query correlata processandola con un modello di canonicalizzazione addestrato. Definisce un mapping tra la query originale e la variante ben formata. Successivamente, quando la query originale viene sottomessa, causa il rendering di una versione selezionabile della variante ben formata e, se selezionata, fornisce la query correlata (non la variante) al sistema di ricerca per generare risultati.

La rivendicazione 2 specifica che la generazione avviene solo dopo aver determinato che la query correlata non è ben formata. Le rivendicazioni 3 e 4 chiariscono che una query non ben formata può essere non grammaticale o non essere una domanda esplicita, mentre la variante è grammaticale ed è una domanda. La rivendicazione 5 specifica che il modello di canonicalizzazione è un sequence-to-sequence model, e la 6 che include un encoder e decoder basati su reti neurali ricorrenti.

La rivendicazione indipendente 7 descrive un metodo che riceve una query in linguaggio naturale, processa le sue feature usando un modello di classificazione addestrato per generare una probabilità che indica quanto la query si conforma a regole grammaticali, e determina se è ben formata. Se non lo è, genera una variante usando un modello di canonicalizzazione, fornisce la variante al sistema di ricerca e causa il rendering dei risultati corrispondenti alla variante. Se è ben formata, fornisce la query originale al sistema.

Le rivendicazioni 8-9 specificano che le feature processate possono includere caratteri, parole, parti del discorso, character n-grams, word n-grams, part-of-speech n-grams. La rivendicazione 10 indica che la probabilità è un valore tra zero e uno. Le rivendicazioni 12-13 descrivono l'addestramento: il modello di canonicalizzazione su coppie di query non ben formate e ben formate, il modello di classificazione su query con indicazione di well-formedness.

La rivendicazione indipendente 15 descrive una variante in cui, invece di fornire automaticamente risultati per la variante ben formata, il sistema causa il rendering di un'indicazione che la query non è ben formata insieme alla variante stessa, lasciando all'utente la scelta.

> LETTURA SEO (INTERPRETAZIONE)

La descrizione contempla che una query è considerata ben formata quando è grammaticalmente corretta, non contiene errori di spelling ed è una domanda esplicita (paragrafo che inizia con "Well-formedness is an indication"). Ad esempio, "What are directions to Hypothetical Café?" è ben formata mentre "Hypothetical Café directions" non lo è.

Il sistema contempla l'uso di feature linguistiche multiple come input: caratteri, parole, parti del discorso, entità, rappresentazioni come bag of words, n-grams di varia dimensione (descrizione del classification engine 106). La descrizione menziona esplicitamente la concatenazione di word n-grams, character n-grams e part-of-speech n-grams come input al modello di classificazione. Il modello di classificazione contempla feed-forward layers seguiti da softmax layers che generano una probabilità tra 0 e 1 indicante la well-formedness (FIG. 2, blocchi 204-206).

Il modello di canonicalizzazione contemplato è un sequence-to-sequence con encoder RNN e decoder RNN, potenzialmente con unità LSTM o GRU (descrizione canonicalization engine 116). L'addestramento contempla l'uso di coppie di query con stesso intent dove la prima non è ben formata e la seconda lo è, come "today date" e "What is today's date" o "painter mona lisa" e "who painted the mona lisa" (FIG. 3, training instance 302).

Per la SEO, questo potrebbe significare che Google dispone della capacità tecnica di riscrivere query mal formate in domande esplicite prima di processarle. Questo potrebbe influenzare quali contenuti vengono considerati rilevanti: contenuti ottimizzati per rispondere a domande esplicite e grammaticali potrebbero essere favoriti rispetto a contenuti ottimizzati per keyword frammentate. Tuttavia, la rivendicazione 1 specifica che quando viene selezionata la variante ben formata, il sistema fornisce la query correlata originale (non la variante) al search system, il che suggerirebbe che la riscrittura serve principalmente per l'interfaccia utente piuttosto che per il ranking.

La descrizione contempla anche l'uso per query correlate ("people also search for"), dove varianti ben formate di query correlate vengono presentate al posto delle query originali mal formate (processo 800, FIG. 9C esempio con "how to reset hypothetical router" come variante di "reset hypothetical router"). Questo potrebbe significare che l'ottimizzazione per varianti ben formate di query correlate potrebbe aumentare la visibilità in questi suggerimenti.

La descrizione enfatizza ripetutamente il risparmio di risorse: il modello di canonicalizzazione viene utilizzato solo dopo che il modello di classificazione determina che la query non è ben formata ("conserving resources of a client device and/or a server device by only selectively generating the well-formed variant"). Questo suggerisce un'implementazione pragmatica focalizzata sull'efficienza.

> COSA NON DIMOSTRA

  • Il brevetto non dimostra che Google applichi questa canonicalizzazione al ranking dei risultati: la rivendicazione 1 specifica che viene fornita la query correlata originale al search system, non la variante ben formata.
  • Non specifica quale peso abbiano le query ben formate rispetto a quelle mal formate nel determinare la rilevanza dei contenuti, né se la riscrittura influenzi algoritmi di ranking.
  • La descrizione contempla l'applicazione principalmente per migliorare l'interfaccia utente e i suggerimenti di query correlate, non necessariamente per modificare il retrieval dei documenti.
  • Essendo parte di una famiglia con continuation (US11423068B2), le rivendicazioni potrebbero sovrapporsi e non rappresentano necessariamente implementazioni indipendenti.

> COSA FARE COMUNQUE

  1. Ottimizzare i contenuti per rispondere a domande esplicite e grammaticalmente corrette, non solo a keyword frammentate, poiché gli utenti potrebbero essere esposti a riformulazioni delle loro query.
  2. Considerare le varianti ben formate delle query target durante la ricerca di parole chiave, specialmente per query informazionali che potrebbero essere riformulate come domande esplicite.
  3. Strutturare i contenuti in formato domanda-risposta può allinearsi meglio con come il sistema potrebbe presentare le query agli utenti, facilitando la comprensione dell'intent.
  4. Monitorare le query correlate suggerite da Google per le proprie query target, poiché potrebbero essere presentate in forma canonicalizzata e rappresentare opportunità di contenuto aggiuntivo.
