> BREVETTO CONCESSO · US11093813B2

Reti neurali per identificare risposte a domande

Titolo originale: Answer to question neural networks

Il brevetto descrive un sistema basato su reti neurali per valutare quanto bene un passaggio di testo risponde a una domanda o per generare una domanda a cui un passaggio risponde. Il sistema utilizza un encoder per rappresentare il passaggio, un decoder RNN che processa la domanda token per token, e due reti neurali parallele: una per l'attenzione e una per il matching, quest'ultima usata per calcolare uno score di risposta.

> COSA RIVENDICA

Le rivendicazioni indipendenti (1, 11, 18) coprono un metodo e un sistema che ricevono un passaggio di testo composto da passage token e una question string composta da question token distribuiti su più time step. Il metodo prevede di processare il passaggio con un encoder neural network per generare una encoded representation per ciascun passage token. A ogni time step, il sistema processa un decoder input usando un decoder neural network: il decoder input comprende almeno il token precedente nella question string e lo stato interno precedente del decoder, e il decoder aggiorna il proprio stato interno. Parallelamente, a ogni time step il sistema processa le encoded representations e un output precedente del decoder usando due reti neurali distinte: una matching vector neural network che genera un matching vector per il time step, e una attention vector neural network che genera un attention vector per il time step, dove l'attention vector include un valore per ciascun passage token. Infine, il sistema genera un answer score che indica quanto bene il passaggio risponde alla domanda, basandosi almeno sui matching vector di tutti i time step.

Le rivendicazioni dipendenti aggiungono dettagli rilevanti. La rivendicazione 2 specifica che l'attention vector ha la stessa dimensionalità del matching vector. La rivendicazione 3 indica che l'attention vector neural network ha la stessa architettura della matching vector neural network ma valori di parametri differenti. La rivendicazione 4 prevede che il decoder input a ogni time step includa anche l'attention vector per quel time step. La rivendicazione 5 specifica che generare l'answer score comprende determinare un matching vector score calcolando una media o una media ponderata delle entries dei matching vector per tutti i time step. La rivendicazione 6 aggiunge che il decoder neural network genera anche un set di question token scores che include uno score per ciascun question token in un vocabolario di possibili question token. La rivendicazione 7 prevede che l'answer score sia generato determinando un perplexity score dalla perplexity media dei question token nella input question string come riflesso dai question token scores generati dal decoder, e combinando il perplexity score con il matching vector score. La rivendicazione 10 contempla che, se l'answer score indica che il passaggio risponde alla domanda, il sistema outputti dati derivati dal passaggio.

> LETTURA SEO (INTERPRETAZIONE)

La descrizione contempla un sistema che può operare in due modalità: valutare quanto bene un passaggio risponde a una domanda data, oppure generare una domanda a cui un passaggio risponde. Il sistema è descritto come particolarmente efficiente perché codifica un singolo passaggio relativamente lungo e poi valuta multiple domande relativamente brevi, invece del contrario, riducendo il carico computazionale. La descrizione menziona esplicitamente un caso d'uso in cui una search query classificata come domanda riceve come risposta un passaggio selezionato tramite questo sistema, che viene presentato insieme ai risultati di ricerca o verbalizzato in risposta a una voice query (paragrafi relativi a FIG. 3, step 308).

Il training del sistema è descritto in FIG. 5 e avviene in due fasi. Nella prima fase (step 502-504), il sistema viene addestrato su coppie passaggio-domanda dove il passaggio è una risposta di alta qualità, usando una loss function che combina average token perplexity loss e pseudo Huber loss, con peso significativamente maggiore sulla perplexity. Nella seconda fase (step 506-508), il sistema viene addestrato su coppie di qualità variabile, dove alcuni passaggi non sono buone risposte, e il peso viene spostato significativamente verso la pseudo Huber loss per insegnare al sistema a discernere tra risposte buone e mediocri o cattive. Questo training in due fasi potrebbe essere rilevante per comprendere come il sistema impara a valutare la qualità delle risposte.

La descrizione sottolinea che il sistema può pre-computare gli answer score per coppie passaggio-domanda e memorizzarli, riducendo il tempo di elaborazione quando una query viene effettivamente posta. Il matching vector neural network e l'attention vector neural network hanno la stessa architettura ma parametri differenti dopo il training, perché servono scopi diversi: l'attention vector viene usato come input al decoder, mentre il matching vector viene usato solo per calcolare l'answer score finale. Il sistema potrebbe quindi valutare non solo se un passaggio risponde a una domanda, ma quanto bene lo fa, distinguendo risposte eccellenti da risposte mediocri. Questo potrebbe essere rilevante per la selezione di featured snippet o risposte dirette, se il sistema fosse applicato in produzione.
