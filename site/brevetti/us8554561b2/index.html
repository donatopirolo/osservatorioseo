> BREVETTO CONCESSO · US8554561B2

Indicizzazione efficiente di documenti con contenuto simile

Titolo originale: Efficient indexing of documents with similar content

Il brevetto affronta il problema dell'indicizzazione di grandi quantità di documenti che condividono porzioni di contenuto (boilerplate, versioni simili, pagine dello stesso dominio). Invece di eliminare i duplicati, il sistema raggruppa i documenti in cluster, comprime le sequenze di token eliminando le ripetizioni interne ai cluster e indicizza solo la versione compressa, mantenendo istruzioni per ricostruire i documenti originali.

> COSA RIVENDICA

La rivendicazione indipendente 1 copre un metodo che raggruppa un insieme di documenti in una pluralità di cluster, dove ciascun cluster include uno o più documenti e un cluster contiene dati corrispondenti a più documenti inclusi un primo e un secondo documento. Il sistema determina che il secondo documento include dati duplicati rispetto al primo documento, identifica un sottoinsieme dei dati del cluster che esclude almeno una parte dei dati duplicati e genera un indice di questo sottoinsieme.

La rivendicazione 2 specifica che i cluster possono essere distribuiti su sistemi informatici diversi. La rivendicazione 3 introduce identificatori multipli per i documenti: un identificatore globale rispetto all'intero repository e un identificatore locale rispetto a una porzione del repository. La rivendicazione 4 chiarisce che la generazione dell'indice esclude l'indicizzazione dei dati duplicati.

Le rivendicazioni 5-9 aggiungono dettagli sulla compressione. La rivendicazione 5 specifica che l'identificazione del sottoinsieme include la generazione di dati compressi del cluster che non includono almeno una parte dei dati duplicati. La rivendicazione 6 introduce un riordinamento: i cluster a documento singolo precedono i cluster multi-documento nella sequenza. La rivendicazione 7 descrive la rappresentazione dei documenti come sequenza di token e introduce i "document reconstruction data" per ricostruire i documenti dai dati compressi, utilizzati per identificare documenti che corrispondono a una query basandosi sulle posizioni dei token.

La rivendicazione 8 copre un processo di query in cui il sistema cerca attraverso i dati compressi dei cluster per occorrenze dei token della query: se un cluster compresso include tutti i token della query, il sistema determina se contiene un documento corrispondente; altrimenti elimina i documenti di quel cluster da ulteriore considerazione. La rivendicazione 9 aggiunge che per query con sequenze specifiche di token, il sistema determina se i token appaiono nella sequenza richiesta usando i document reconstruction data.

Le rivendicazioni 10-13 specificano criteri di clustering. La rivendicazione 10 copre il raggruppamento basato sull'analisi del contenuto. La rivendicazione 11 copre il raggruppamento basato sui resource locator (URL). La rivendicazione 12 specifica l'ordinamento dei documenti secondo i resource locator e la selezione di documenti consecutivi dall'ordinamento per formare cluster. La rivendicazione 13 descrive la modifica degli URL prima dell'ordinamento: i domini vengono invertiti e l'indicatore di protocollo spostato alla fine (es. "http://www.yahoo.com/index.html" diventa "com.yahoo.www/index.html:http").

La rivendicazione 14 copre l'applicazione a archivi storici: un cluster può includere diverse versioni dello stesso documento da tempi diversi. Le rivendicazioni 15-29 replicano le stesse protezioni per implementazioni come sistema informatico e computer readable storage medium.

> LETTURA SEO (INTERPRETAZIONE)

La descrizione contempla un sistema di compressione basato sul metodo Bentley-McIlroy o varianti simili (blocchi 306, 1002-1032, Figure 8-10). I documenti vengono rappresentati come sequenze di token di lunghezza fissa, tipicamente 32 bit (blocco 106, memoria 206). La descrizione specifica che token ripetuti vengono elisi dalla memorizzazione solo se la sequenza ripetuta supera una lunghezza minima predefinita N, che in alcune implementazioni è di venti token (blocco 306).

Il clustering basato su URL invertiti (rivendicazione 13, blocco 304) è descritto come metodo per raggruppare documenti dallo stesso sotto-dominio, che tendono ad avere sequenze di token comuni come testo boilerplate. La descrizione contempla che K documenti consecutivi dall'ordinamento formino un cluster, dove K può essere 10 in alcune implementazioni (blocco 304). Il posizionamento dei cluster a documento singolo prima dei cluster multi-documento (rivendicazione 6, Figura 7) allinea le posizioni dei token nello spazio compresso e non compresso per quei documenti.

La descrizione introduce una "compressed-uncompressed map" (elemento 226) che mappa posizioni nella sequenza compressa a una o più posizioni nella sequenza non compressa, creando mappature uno-a-molti quando un token compresso corrisponde a più istanze nel non compresso. I "document reconstruction data" (elemento 224) includono codici Add (sequenze di token letterali) e codici Copy (che specificano range di posizioni da duplicare), con i codici Copy che possono includere posizione di inizio e lunghezza (blocchi 608, 830).

Per le query, la descrizione contempla un processo a due fasi (Figura 4): prima si identificano cluster che contengono i token della query (blocco 404), eliminando cluster che non possono soddisfare la query senza decodificare; poi si identificano documenti effettivi all'interno dei cluster selezionati (blocco 406). Per query con operatore AND, solo i cluster contenenti tutti i token vengono considerati (blocco 508). Per query di frase esatta, la descrizione contempla l'accorciamento dei codici Copy di alcuni token alle estremità durante la codifica, fino a separatori di frase come punteggiatura (blocco 512), per ridurre casi in cui frasi corrispondenti attraversano transizioni Add-Copy.

Per la SEO, questo potrebbe significare che Google avrebbe potuto sviluppare sistemi di indicizzazione che non eliminano completamente i duplicati ma li comprimono mantenendoli accessibili. Il clustering per dominio inverso suggerirebbe che contenuti boilerplate comuni su un sito potrebbero essere gestiti in modo più efficiente senza penalizzare ogni pagina. La soglia di venti token per l'elision potrebbe indicare che ripetizioni molto brevi non vengono considerate duplicazione significativa. Tuttavia, questo riguarda l'architettura di indicizzazione interna, non necessariamente i criteri di ranking o la selezione di URL canonici mostrati agli utenti.

> COSA FARE COMUNQUE

  1. Contenuti boilerplate estesi (header, footer, sidebar identici) su molte pagine di un sito sono tecnicamente gestibili dai motori senza necessariamente penalizzare ogni pagina, ma differenziare i contenuti unici resta buona pratica per l'utente.
  2. Versioni multiple dello stesso contenuto con URL diversi potrebbero essere tecnicamente indicizzabili tutte, ma la scelta di quale mostrare dipende da altri fattori non coperti da questo brevetto: continuare a usare canonical e redirect appropriati.
  3. La soglia di lunghezza minima per considerare ripetizioni (venti token nella descrizione) suggerisce che frasi brevi ripetute non costituiscono necessariamente duplicazione problematica dal punto di vista tecnico.
  4. Documenti con contenuto sostanzialmente identico ma timestamp e URL diversi possono coesistere nei sistemi di indicizzazione: concentrarsi sulla differenziazione del valore per l'utente piuttosto che su micro-ottimizzazioni di duplicazione.

> TERMINI CHIAVE

cluster
Raggruppamento di uno o più documenti con contenuto correlato o simile, processati insieme per identificare ed elidere dati duplicati
token
Oggetto di lunghezza fissa (es. 32 bit) che rappresenta un termine, parola, simbolo di punteggiatura o tag HTML nel documento
compressed sequence of tokens
Sequenza di token in cui alcune ripetizioni sono state elise dalla memorizzazione, mantenendo solo occorrenze uniche e istruzioni per ricostruire le ripetizioni
document reconstruction data
Istruzioni (codici Add e Copy) che permettono di ricostruire i documenti originali dalla sequenza compressa di token
Copy code
Istruzione che specifica un range di posizioni nella sequenza compressa da duplicare per ricostruire una porzione di documento
Add code
Istruzione che include una sequenza di token letterali o riferisce a una sequenza di token nella sequenza compressa
compressed-uncompressed map
Mappatura tra posizioni dei token nella sequenza compressa e le corrispondenti posizioni (una o più) nella sequenza non compressa
