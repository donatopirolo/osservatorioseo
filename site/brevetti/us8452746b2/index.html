> BREVETTO CONCESSO · US8452746B2

Rilevamento di spam nei risultati di ricerca elaborati con contesto

Titolo originale: Detecting spam search results for context processed search queries

Il brevetto descrive un sistema di ricerca programmabile da terze parti tramite file di contesto che controllano query e risultati. Il sistema identifica e filtra contesti e risultati spam provenienti da provider di contenuti verticali, sia in fase offline (analizzando i file di contesto) sia durante l'elaborazione delle query (confrontando i risultati con filtri spam e con risultati nativi non elaborati).

> COSA RIVENDICA

La rivendicazione indipendente 1 copre un metodo implementato al computer che riceve una query di ricerca e l'identificazione di un file di contesto da un provider di contenuti terzo. Il sistema elabora il file di contesto per identificare comandi per processare la query e i risultati, inclusi comandi con precondizioni per la valutazione di altri comandi. La query viene elaborata secondo questi comandi per produrre query elaborate dal contesto, ottenendo risultati di ricerca che vengono poi processati secondo i comandi per i risultati. Il metodo analizza se una voce corrispondente in un file di annotazione si riferisce a spam per ciascuno dei risultati elaborati dal contesto. I risultati identificati come spam vengono rimossi per creare risultati modificati che vengono forniti al dispositivo client.

Le rivendicazioni dipendenti aggiungono dettagli rilevanti. La rivendicazione 2 contempla che il file di contesto possa riferirsi a file di contesto correlati. La rivendicazione 3 specifica che l'elaborazione della query può includere la valutazione di una proprietà della query rispetto a una proprietà predefinita o la modifica della query stessa. La rivendicazione 4 indica che ogni voce nel file di annotazione comprende un link a una pagina web, con determinazione se la pagina contiene spam. La rivendicazione 12 contempla che le annotazioni comprendano etichette selezionabili per generare nuovi risultati associati a metadati che includono l'etichetta. La rivendicazione 13 specifica operazioni di pre-elaborazione come selezione di una collezione di documenti, impostazione di parametri del motore di ricerca, o filtraggio dei risultati per tipo designato. La rivendicazione 19 descrive l'identificazione di un file di contesto correlato contenente annotazioni per determinare quali si riferiscono a spam.

> LETTURA SEO (INTERPRETAZIONE)

La descrizione contempla un sistema di ricerca programmabile in cui provider di contenuti verticali possono fornire file di contesto che controllano pre-elaborazione delle query, parametri del motore di ricerca e post-elaborazione dei risultati. Questi file di contesto includono comandi per modificare query, selezionare collezioni di documenti, filtrare e annotare risultati (paragrafi relativi a FIGS. 4-8).

Il sistema implementa due fasi di rilevamento spam. La fase offline (FIG. 10) analizza i file di annotazione sito/pagina ricevuti dai provider verticali tramite un filtro spam. Se oltre il 40% delle pagine elencate in un file di annotazione è spam, il provider viene classificato come biased e i suoi file di contesto vengono esclusi dall'elaborazione delle query dirette degli utenti. La fase query-time (FIG. 11) applica un filtro spam ai risultati elaborati dal contesto, calcolando uno spam score medio. Se questo supera una soglia predeterminata o se la percentuale di risultati spam supera il 40%, il provider viene identificato come spam e i suoi contenuti vengono rimossi dai risultati filtrati.

La descrizione contempla anche un algoritmo di rilevamento bias che confronta i risultati elaborati dal contesto con i risultati nativi della query originale usando una misura di distanza. Se la distanza supera una soglia, il provider è considerato biased e i suoi file di contesto non vengono usati nel post-processing. La misura di distanza può essere la percentuale di risultati identici o da siti identici.

Per la SEO, questo potrebbe significare che motori di ricerca potrebbero valutare la qualità dei contenuti non solo direttamente ma anche attraverso l'analisi di come terze parti (provider verticali) categorizzano e annotano i siti. Siti frequentemente etichettati come spam in file di annotazione di terze parti potrebbero essere penalizzati. Tuttavia, l'architettura descritta riguarda specificamente un sistema programmabile da terze parti, non necessariamente il funzionamento standard di Google Search.

> COSA NON DIMOSTRA

  • Il brevetto è scaduto (Expired - Fee Related dal 2013), quindi non rappresenta protezione attiva né prova di implementazione corrente in alcun sistema di ricerca.
  • L'ambito copre un sistema di ricerca programmabile da terze parti tramite file di contesto, un'architettura non dimostrata essere in uso in Google Search web standard.
  • Il brevetto descrive meccanismi di rilevamento spam specifici per contesti forniti da terze parti, non necessariamente applicabili al ranking organico generale.
  • Non fornisce evidenza che Google utilizzi soglie specifiche come il 40% di contenuti spam per penalizzare siti, né che confronti risultati contestuali con risultati nativi per rilevare bias nel ranking organico.

> COSA FARE COMUNQUE

  1. Evitare pratiche che potrebbero far classificare un sito come spam da filtri automatici, indipendentemente dal contesto di terze parti, mantenendo contenuti genuini e non manipolativi.
  2. Considerare che la reputazione di un sito potrebbe essere influenzata da come viene categorizzato e annotato da terze parti autorevoli, anche se questo brevetto specifico non è in uso.
  3. Mantenere coerenza tra contenuti e aspettative degli utenti per evitare che risultati appaiano eccessivamente distanti da ricerche native non manipolate.
  4. Documentare trasparentemente eventuali relazioni commerciali che influenzano contenuti o link, dato che sistemi di rilevamento bias potrebbero identificare discrepanze significative tra risultati attesi e forniti.
