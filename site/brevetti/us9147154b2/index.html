> BREVETTO CONCESSO · US9147154B2

Classificazione di risorse tramite reti neurali profonde

Titolo originale: Classifying resources using a deep network

Il brevetto descrive un sistema che utilizza una rete neurale profonda per classificare risorse web in categorie predeterminate. Il sistema riceve feature di una risorsa, le trasforma in rappresentazioni numeriche tramite funzioni di embedding, le elabora attraverso strati neurali non lineari e genera punteggi che indicano la probabilità che la risorsa appartenga a ciascuna categoria.

> COSA RIVENDICA

Le rivendicazioni indipendenti (1, 10, 17) proteggono un sistema, un metodo e un programma per computer che implementano una rete neurale profonda per la classificazione di risorse. Il sistema riceve in input una pluralità di feature di una risorsa, dove ciascuna feature è il valore di un rispettivo attributo della risorsa. Ogni feature viene processata attraverso una rispettiva funzione di embedding per generare valori numerici. Questi valori numerici vengono poi elaborati da uno o più strati di rete neurale che applicano trasformazioni non lineari per generare una rappresentazione alternativa delle feature. Infine, un classificatore processa questa rappresentazione alternativa per generare un punteggio per ciascuna categoria in un insieme predeterminato di categorie, dove ogni punteggio misura la probabilità prevista che la risorsa appartenga alla categoria corrispondente.

Le rivendicazioni dipendenti aggiungono dettagli rilevanti. Le rivendicazioni 2, 11 e 18 specificano che ciascuna funzione di embedding può essere specifica per feature di un rispettivo tipo. Le rivendicazioni 3, 12 e 19 indicano che l'insieme predeterminato di categorie può includere una categoria spam per motori di ricerca, con il punteggio che misura la probabilità che la risorsa sia spam. Le rivendicazioni 4, 13 e 20 estendono questo concetto specificando che l'insieme può includere una categoria per ciascun tipo di spam tra più tipi diversi. Le rivendicazioni 5, 14 e 21 contemplano che l'insieme possa includere una categoria per ciascun tipo di risorsa in un gruppo di tipi di risorsa.

Particolarmente rilevanti per la SEO sono le rivendicazioni 6, 15 e 22, che specificano che i punteggi di categoria possono essere forniti a un sistema di ricerca per determinare se indicizzare o meno le risorse in un indice del motore di ricerca. Le rivendicazioni 7, 16 e 23 indicano che i punteggi possono essere forniti a un sistema di ricerca per generare e ordinare i risultati di ricerca in risposta a query ricevute. Le rivendicazioni 8 e 9 specificano che i valori numerici possono essere valori in virgola mobile o valori interi quantizzati la cui codifica rappresenta valori in virgola mobile.

> LETTURA SEO (INTERPRETAZIONE)

La descrizione contempla diverse implementazioni del sistema di classificazione. Il paragrafo relativo alla FIG. 2 specifica che le feature della risorsa includono token dal contenuto della risorsa, opzionalmente associati a etichette che corrispondono a porzioni specifiche come il titolo, l'header o i link. La descrizione indica inoltre che le feature possono includere l'URL della risorsa, il nome di dominio, l'età della risorsa e la lunghezza della risorsa. Vengono anche contemplate feature che identificano categorie o tipi di entità rilevanti per la risorsa, oltre a feature ottenute da altri sistemi che riassumono il contenuto o l'utilità della risorsa.

La descrizione contempla tre tipi principali di funzioni di embedding: simple embedding function (mappa un singolo token in un vettore), parallel embedding function (mappa una lista di token in vettori concatenati), combining embedding function (mappa token in vettori che vengono poi fusi tramite funzioni lineari o non lineari) e mixed embedding function (combina gli approcci precedenti). Questi dettagli tecnici suggeriscono che il sistema potrebbe essere in grado di processare sia singoli termini che sequenze di termini con diversi livelli di sofisticazione.

Per quanto riguarda l'applicazione alla ricerca, la descrizione contempla che il sistema di ricerca potrebbe utilizzare i punteggi di categoria per determinare se indicizzare una risorsa: una risorsa con alta probabilità di essere spam sarebbe meno probabile che venga indicizzata. La descrizione contempla anche che i punteggi potrebbero essere utilizzati per rimuovere risultati di ricerca prima della presentazione all'utente o per demotare risultati nell'ordine di presentazione. Quando i punteggi rappresentano la probabilità di appartenenza a tipi di risorsa specifici, la descrizione contempla che potrebbero essere utilizzati per promuovere o demotare risultati in risposta a query specifiche.

Un aspetto interessante contemplato nella descrizione è l'uso dei punteggi per verificare dichiarazioni degli utenti sulle risorse, ad esempio quando un utente segnala che una risorsa è stata classificata erroneamente. Il sistema potrebbe utilizzare i punteggi generati per valutare la probabilità di misclassificazione e determinare se aggiustare la classificazione.

Tuttavia, è importante sottolineare che questi sono scenari contemplati nella descrizione come possibili implementazioni. Il brevetto non afferma che Google utilizzi attivamente questo sistema in produzione né specifica quali feature esatte vengano utilizzate o quale peso abbiano nella classificazione finale.

> TERMINI CHIAVE

embedding function
Funzione che trasforma feature discrete (come token di testo) in rappresentazioni numeriche (vettori) che possono essere elaborate da una rete neurale
deep network
Rete neurale con più strati che applica trasformazioni non lineari successive per generare una rappresentazione alternativa dell'input
category score
Punteggio numerico che rappresenta la probabilità prevista che una risorsa appartenga a una specifica categoria predeterminata
alternative representation
Rappresentazione trasformata delle feature originali generata dagli strati neurali, utilizzata dal classificatore per predire i punteggi di categoria
feature type
Tipo categoriale di una feature, ad esempio token dal titolo, dall'URL o dal contenuto, ciascuno processato da una specifica funzione di embedding
